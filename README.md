# คีย์เลข

ระบบคีย์หวยภาษาไทย โทนพาสเทลส้ม–ทอง–ขาว รองรับ desktop/mobile แยกสิทธิ์ Admin, Leader, Member ใช้ React + Vite + Tailwind CSS + Axios + Socket.IO และ Express + MySQL

ความต้องการทั้งหมด: [REQUIREMENTS.md](REQUIREMENTS.md) / ข้อความต้นฉบับ: [REQUIREMENTS-ORIGINAL.txt](REQUIREMENTS-ORIGINAL.txt)

## เริ่มใช้งาน

ตอนพัฒนาได้สร้าง `mysql-kuayrai` ใน Compose project `docker` ที่พอร์ต 3308 แล้ว โดยไม่เปลี่ยน `mysql-twiniiz` พอร์ต 3307 ข้อมูลเชื่อมต่ออยู่ในไฟล์ `.env` ที่ไม่เข้า Git

เปิดสอง terminal:

```sh
cd backend
npm install
npm start
```

```sh
cd frontend
npm install
npm start
```

หน้าเว็บ http://127.0.0.1:5173 / API http://127.0.0.1:4000

บัญชีแรก `admintor` และ `adminmike` รหัสเริ่มต้น `password` ระบบบังคับเปลี่ยนรหัสผ่านก่อนใช้งาน บัญชีทั้งสองไม่มีสิทธิ์คีย์โพย ให้ Admin สร้าง Leader แล้ว Leader สร้าง Member ตามลำดับ

ขั้นตอนเริ่มเครือข่าย:

1. Admin เปลี่ยนรหัสผ่าน → ตั้งค่า → สร้าง Leader พร้อมวันหมดอายุ
2. Admin เพิ่มงวดและระบุเวลาเผยแพร่ผล
3. Leader เปลี่ยนรหัสผ่าน → ตั้งค่าอัตราจ่าย วงเงินรายประเภทเลข และกฎรายงวด (เวลาปิดรับ เลขอั้น จ่ายครึ่ง)
4. Leader → บัญชี → สร้าง Member
5. Member เปลี่ยนรหัสผ่าน → คีย์ → เลือกงวด → เพิ่มเลข → ตรวจสรุปลูกค้า → ยืนยันส่ง
6. Admin บันทึกผลก่อนเวลาได้ แต่ Member/Leader จะเห็นเมื่อถึงเวลาเผยแพร่

## ติดตั้งใหม่บนเครื่องอื่น

```sh
cp docker/.env.example docker/.env
cp backend/.env.example backend/.env
```

แก้รหัส MySQL ให้ตรงกันทั้งสองไฟล์ ตั้ง JWT_SECRET เป็นค่า random อย่างน้อย 32 ตัวอักษร จากนั้น:

```sh
docker compose --env-file docker/.env -f docker/compose.yml up -d mysql-kuayrai
cd backend
npm install
npm run seed
npm start
```

Schema ถูก import ครั้งแรกเมื่อ volume ว่างเท่านั้น `npm run seed` สร้าง Admin แบบไม่ทับบัญชีเดิม ห้ามใช้ `--remove-orphans` เพราะ MySQL ของระบบอื่นอยู่ใน project docker เดียวกัน ห้าม `down -v` เมื่อมีข้อมูลใช้งาน

ค่าเริ่มต้นเวลาธุรกิจ Asia/Bangkok API แปลงเวลาจาก datetime-local เป็น +07:00 และ MySQL connection ใช้ +07:00 เวลาออกผลเก็บแยกจากวันงวด

## สิ่งที่ทำแล้ว

- Login, hash password, JWT, role guard, เปลี่ยนรหัสครั้งแรก/ภายหลัง, บล็อกเครือข่ายหมดอายุ
- สร้าง Leader/Member พร้อม username ไม่ซ้ำ รหัสเริ่มต้นสุ่ม การต่ออายุ/ระงับ Leader
- จัดการหวย เปิด/ปิด เพิ่ม/แก้ไข/ลบประเภทหรืองวดที่ยังไม่มีข้อมูลอ้างอิง บันทึกผล เผยแพร่ตามเวลา
- ตั้งอัตราจ่ายและวงเงินแยกประเภทเลข / ตั้งเลขอั้น จ่ายครึ่ง ปิดรับแยกรายงวด
- คีย์ 2 ตัว, 3 ตัว, 6 กลับ, รูด, วิ่ง, วิน / ตัวช่วยเบิ้น–ตอง / วางข้อความพร้อมราคาแล้วดึงเฉพาะเลข
- รวมโพย ตรวจเลขอั้นและวงเงิน บันทึกยอดเต็มและ snapshot อัตราจ่าย
- Transaction และล็อกเครือข่ายป้องกัน concurrent overselling / แก้ไขโพย / ยกเลิกโพยได้ครั้งเดียว
- Socket.IO อัปเดตความจุรับซื้อ และแจ้งเตือน / โหลดใหม่เมื่อ reconnect / ตัด socket เครือข่ายหมดอายุ
- โพยล่าสุด 5 รายการ รายละเอียดโพย กรองชนิด/งวด/สมาชิก/ช่วงวัน
- สรุปลูกค้าแบบเลขรวมกลุ่ม top×bottom / Copy ภาพผ่าน clipboard
- Dashboard ยอดขาย จำนวนโพย ยอดถูกรางวัล กราฟยอดแยกประเภท และรายสมาชิก/Leader
- Custom modal ภาษาไทย ไม่ใช้ alert() หรือ confirm()

## การตรวจสอบ

```sh
cd frontend
npm run build
npm test
```

```sh
cd backend
npm test
npm run test:integration
```

Integration test ต้องมี MySQL และ API รันอยู่ สร้างบัญชีและงวดที่ชื่อขึ้นต้น test_ แล้วลบเฉพาะ fixture เมื่อจบ ไม่เปลี่ยนบัญชี Admin ที่ seed สำหรับผู้ใช้

ตรวจแล้ว: build production, unit tests ด้านราคา/รูปแบบเลข และ API integration ครอบคลุมสิทธิ์ ค่าเริ่มต้นเปลี่ยนรหัส การส่งโดยไม่ใช้เครดิต/ส่วนลด แก้/ยกเลิก เลขอั้น ส่งพร้อมกัน ผลก่อนเวลา และหมดอายุ Leader หน้า login ตรวจในเบราว์เซอร์แล้ว ยังต้องตรวจการคัดลอกภาพจริงและทุกหน้าบนมือถือกับ workflow ของผู้ใช้ก่อนใช้งานจริง

## ขอบเขตและการใช้งานจริง

ระบบชุดนี้เป็นรุ่นเริ่มต้นสำหรับทดสอบ workflow ในเครื่อง ยังไม่ deploy ไป VPS/โดเมน การบันทึกผลแสดงยอดชนะในสถิติ เพื่อสรุปข้อมูลเท่านั้น ไม่มีระบบเครดิต ส่วนลด ค่าคอม หรือชำระเงิน

- LINE OA เป็นงานระยะถัดไป ยังไม่เชื่อมกับบัญชีภายนอก
- การลบ Leader ใช้การระงับเพื่อรักษาประวัติ Member/โพย ไม่มี hard delete เครือข่าย
- การสร้างงวดเป็น manual ยังไม่มีการสร้างตามปฏิทินอัตโนมัติ
- ยอดขาย/รางวัลเป็นสรุป ไม่ใช่บัญชีชำระเงินจริง ไม่มีระบบรับโอนเงิน
- ปุ่มช่วยเลขอั้น/โพยล่าสุดแสดงในหน้า ไม่ได้เป็นปุ่มลอยลากย้ายได้
- Copy ภาพต้อง browser รองรับ ClipboardItem และใช้ HTTPS หรือ localhost
- มี Docker production, Nginx, HTTPS และสคริปต์ backup/update แล้ว ดู DEPLOY_GUIDE.md; ต้องตั้ง DNS และติดตั้งบน VPS จริงก่อนเปิดใช้งาน

Member ใช้งานได้โดยไม่ต้องเติมเครดิต Leader ใช้งานได้หนึ่งปีนับจากวันที่สร้าง บัญชีทดสอบไม่บังคับเปลี่ยนรหัสครั้งแรกเพื่อเข้าหน้าทดสอบได้ทันที คำสั่ง seed ไม่ทับรหัสผ่านของบัญชีเดิม

หน้า Login มีปุ่มเข้าใช้งานด่วนสามบทบาทเฉพาะ Vite development mode ปุ่มใช้ API Login ปกติ ไม่ข้ามการตรวจสิทธิ์ และไม่แสดงใน production build ตัว seed ปฏิเสธการทำงานเมื่อ NODE_ENV=production บัญชีทดสอบใช้สำหรับข้อมูลทดสอบในเครื่อง

UI บนมือถือใช้เมนูติดขอบล่างพร้อม safe-area Header ไม่แสดงชื่อ/ภาพย่อผู้ใช้ ฟอนต์ไทยใช้ Mali แบบมีหัวและโหลดจากไฟล์ในโปรเจกต์

### งวดที่แสดงและหน้าเริ่มต้น

หน้าคีย์เลือกงวดอนาคตที่ใกล้เวลาออกผลที่สุดเพียงหนึ่งงวดต่อหวย หน้าผลและตัวเลือกกรองโพยแสดงงวดนั้นพร้อมงวดที่ผ่านมา โดยไม่แสดงงวดอนาคตที่ไกลกว่า เมื่อถึงเวลาออกผลจะเลื่อนไปงวดถัดไปอัตโนมัติ เวลาปิดรับไม่ใช้เป็นตัวเลื่อนงวด เพื่อไม่ข้ามงวดที่ยังรอผล Admin ยังจัดการงวดที่สร้างล่วงหน้าทั้งหมดได้

Member เข้าสู่หน้าคีย์โดยอัตโนมัติ ส่วน Leader และ Admin เข้าหน้าผล เมนูหลักที่เน้นกลางแถบคือคีย์สำหรับ Member และตั้งค่าสำหรับ Leader/Admin

Leader จัดการกฎรายงวดผ่านตัวเลือกงวดแยกตามหวย เริ่มต้นที่งวดใกล้ที่สุด แต่เลือกงวดอนาคตใดก็ได้ที่ยังไม่ถึงเวลาออกผล ฟอร์มจะแสดงวันปิดรับ เลขอั้น และเลขจ่ายครึ่งของงวดที่เลือก พร้อมบันทึกแยกตาม draw ID

### สกุลเงินของโพย

- หน้าคีย์เลือกบาท (ค่าเริ่มต้น) หรือกีบ โดยหนึ่งบิลใช้สกุลเงินเดียว เมื่อเพิ่มรายการแล้วต้องล้างรายการก่อนเปลี่ยนสกุลเงิน บิลที่ส่งแล้วเปลี่ยนสกุลเงินไม่ได้
- กีบใช้หน่วย K: 1 = 1,000 กีบ และ 10 = 10,000 กีบ อัตราจ่ายเป็น K ต่อ 1 K เช่น 95 จ่าย 95,000 กีบเมื่อซื้อ 1,000 กีบ
- Leader ตั้งอัตราจ่ายและวงเงินกีบแยกจากบาทก่อนรับโพยกีบ วงเงินแยกตามสกุลเงิน เลข ประเภท และงวด เลขปิดรับ/จ่ายครึ่งใช้ร่วมกัน
- สถิติเลือกสกุลเงินเพื่อป้องกันการรวมยอดบาทกับกีบ ไม่มีการแปลงอัตราแลกเปลี่ยน
- เก็บสกุลเงินไว้ในแต่ละรายการของ `bills.items` โดยเซิร์ฟเวอร์บังคับให้เหมือนกันทั้งบิล บิลเดิมที่ไม่มีสกุลเงินถือเป็น THB ไม่ต้องปรับโครงสร้างฐานข้อมูล ค่ากีบเก็บใน `settings.config.lak` และจำนวนเงินกีบเก็บเป็น K
